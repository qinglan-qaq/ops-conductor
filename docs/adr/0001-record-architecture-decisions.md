# ADR 0001：记录架构决策

- 状态：已接受
- 日期：2026-11-03

## 背景

项目涉及多 Agent 协作、任务编排、写操作审批与 RAG 检索。关键取舍如果没有记录，后续实现和面试讲解都会退化成口头解释，也容易在迭代中悄悄改变。

## 决策

使用 `docs/adr/NNNN-<slug>.md` 记录架构决策。每条 ADR 包含：状态、背景、决策、理由、后果、备选方案。

只记录难以逆转或影响多个模块的决策，不记录普通实现细节。

## 后果

- 面试时可以直接展示取舍过程，而不是只展示最终架构图。
- 修改核心设计时需要新增 ADR 或标记旧 ADR 为已取代。
- 维护成本很低，每条 ADR 控制在半页到一页。
