# ADR 0002：LLM 规划 + 确定性运行时执行

- 状态：已接受
- 日期：2026-11-03

## 背景

Agent 编排有两条常见路线：纯 ReAct 循环让模型逐步决定下一步；或由 Supervisor 逐个子任务调度。两者都把「每一步做什么」交给模型，延迟不可预算，失败路径难以测试，成本随轮次上升。

电商 ERP 场景对延迟、稳定性和可审计性要求高，且写操作涉及资金与库存。

## 决策

Planner 只负责把自然语言指令拆成带依赖的任务 DAG，声明前置条件、后置条件、超时、重试与补偿。确定性运行时按 DAG 执行，模型只在计划生成、异常归因和重规划时介入。

模型不直接决定「第 3 步调用哪个工具、传什么参数」；工具调用由计划中的节点与参数绑定确定。

## 理由

- 延迟可预算：每个节点有独立超时，任务有总预算。
- 可测试：固定计划可以用 stub 模型稳定复现。
- 可审计：执行路径与审批点明确。
- 成本可控：减少无进展的模型轮次。

## 后果

- 需要维护任务 DAG Schema、工具契约和节点执行语义。
- 灵活性低于纯 ReAct，异常场景依赖重规划与人工升级。
- 计划质量成为关键指标，需要评测集覆盖拆解正确性。

## 备选方案

- **纯 ReAct**：实现快，但延迟与成本不可控，不适合在线业务操作。
- **Supervisor 逐步调度**：可控性较好，但串行等待多，主管转述会引入信息失真。
- **全自治编舞**：适合异步长任务，不适合用户等待回复的主链路；后续只用于批量后台任务。
