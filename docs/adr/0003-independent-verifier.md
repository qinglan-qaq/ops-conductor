# ADR 0003：独立验证 Agent 拥有否决权

- 状态：已接受
- 日期：2026-11-03

## 背景

生成 Agent 容易为自己的输出寻找合理化解释。让同一个模型、同一段上下文「自查」，实际上是自己批自己作业，无法可靠拦截事实错误、越权动作和超范围承诺。

电商 ERP 的错误代价不只是答错，还包括错退款、错改址、错调拨。

## 决策

验证 Agent 与生成 Agent 在提示词、上下文、模型上完全隔离。验证 Agent 只读取证据、计划、工具返回和最终答复，检查：

- 事实是否被证据支持；
- 金额、库存、时效是否与系统返回值一致；
- 工具调用是否越权；
- 是否做出政策范围外的承诺；
- 引用是否有效、是否过期。

验证不通过时拥有阻塞性否决权，任务不得直接输出或执行写操作，必须修正、降级或转人工。

## 理由

- 隔离降低同源偏差。
- 否决权让质量门禁成为硬约束，而不是建议。
- 验证结果本身可审计，便于复盘。

## 后果

- 增加一次模型调用，需要控制成本与延迟。
- 验证规则需要持续维护，否则会漏检或误杀。
- 高风险场景必须保留人工兜底，验证不能替代审批。
