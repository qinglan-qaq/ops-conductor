# 实施计划

> 当前以 3 周 MVP + 3 周 JD 对齐为主线，v1.0 作为后续完整版。

**状态** MVP 待实施 ｜ **当前周期** 6 周（3 周 MVP + 3 周 JD 对齐） ｜ **关联文档**：[系统设计](design.md) ｜ [MVP 设计规格](specs/2026-11-04-mvp-order-exception-design.md) ｜ [JD 对齐设计方案](specs/2026-11-04-jd-alignment-design.md) ｜ [数据来源与合规](data-sources.md)

## 1. 实施原则

- **每周一个可演示增量**，简历与面试材料不等待项目完工。
- **先只读、后写操作**；写操作先具备审批与幂等，再接入演示脚本。
- **时间不足时优先砍场景深度**，不砍审批、幂等、补偿、评测这四项「非 Demo 证据」。
- 每天按 6–8 小时投入估算；若只能业余投入，将每周计划拉长一倍。
- MVP 只做订单异常一个场景；JD 对齐阶段以薄切片补 SKILL、Memory、RAG、RPA、ERP Adapter 和多模型，不扩成完整退款或多仓调拨。

## 2. 当前 MVP：3 周

| 周 | 工作 | 退出标准 | 可演示产出 |
|---|---|---|---|
| 第 1 周 | Alembic 初始迁移、最小领域表、种子数据、只读 MCP 工具、任务提交与计划预览、规则路由、Planner schema + 模板兜底、审计/trace 骨架、只读测试 | 能提交任务并看到结构化计划；只读链路测试通过 | 任务提交 → 计划预览 |
| 第 2 周 | 拆单/改址写工具、审批 API 与控制台、幂等、补偿、Verifier、检查点恢复、失败注入夹具、写操作测试 | 能审批并执行；重复提交不重复写；注入库存冲突能补偿；审计完整 | 审批 → 执行 → 失败补偿 |
| 第 3 周 | 控制台完善、28 条 Golden Tasks、真实模型 5–10 条冒烟、失败注入套件、演示脚本与录屏、指标报告、文档更新 | 评测报告可复现；3 分钟演示可完整走通 | 完整演示 + 评测报告 |

**切线规则**

- 第 2 周延期：先砍控制台样式和真实模型冒烟，不砍审批、幂等、补偿、审计。
- 第 3 周延期：先砍真实模型冒烟，不砍 28 条评测和失败注入。
- 任何情况下不得用「跳过审批」「关闭幂等」「省略补偿」换取进度。

详细需求见 [MVP 设计规格](specs/2026-11-04-mvp-order-exception-design.md)；任务级计划见 [MVP 实施计划](plans/2026-11-04-mvp-order-exception-implementation.md)。

## 3. JD 对齐阶段：MVP 后 3 周

| 周 | 工作 | 退出标准 | 可演示产出 |
|---|---|---|---|
| 第 4 周 | ERP Adapter + 聚水潭契约 mock + 契约测试；SKILL 注册表与订单异常技能；失败记忆与反思循环 | 两个 Adapter 跑同一组契约测试；SKILL 能驱动计划；失败记忆可复用 | ERP 契约测试 + SKILL 驱动计划 |
| 第 5 周 | RAG 政策检索 + 退款资格判定（只判定，不真实退款）；Playwright 旧版打单页 RPA | 退款判定带引用与金额明细；RPA 可操作并留截图与审计 | RAG 引用演示 + RPA 演示 |
| 第 6 周 | 模型网关与路由、成本统计、60+ Golden Tasks、5 分钟演示、ADR 与面试材料 | 60+ 评测可复现；多模型成本可对比；演示完整 | 5 分钟演示 + 成本/评测报告 |

**切线规则**

- 第 4 周延期：先把 Memory 推到第 6 周，保住 Adapter + SKILL。
- 第 5 周延期：RPA 退化为录屏演示，保住 RAG。
- 第 6 周延期：多模型对比减到两个模型，保住 60 条评测和文档。
- 任何情况下不砍审批、幂等、补偿、审计。

详细方案见 [JD 对齐设计方案](specs/2026-11-04-jd-alignment-design.md)；任务级计划见 [JD 对齐实施计划](plans/2026-11-04-jd-alignment-implementation.md)。

## 4. 后续 v1.0 路线

JD 对齐阶段完成后，再扩展为完整版本：

- 完整退款执行：支付/退款模拟、工单回写、对账与失败补偿。
- 完整多仓调拨：库存水位、在途、并发冲突、跨仓一致性。
- 100 条 Golden Tasks、Langfuse trace、成本看板与回归流水线。
- 完整多租户隔离、生产部署、灰度与压测。

## 5. 投递节奏

- 每天固定 1–2 小时投递与沟通，建议每天 5–10 份精准投递，而非海投。
- MVP 第 2 周出现可演示的写闭环后即可开始带项目投递，不必等评测全部完成。
- JD 对齐阶段每完成一周，更新简历、项目链接与一页纸进展。
- 优先投电商 SaaS、ERP、客服 SaaS、RPA、AI Agent 方向。
- 岗位关键词：AI Agent 工程师、LLM 应用工程师、AI 后端、智能体平台。

## 6. 交付物

### MVP 交付物

- 一条命令启动的 Docker Compose 环境与种子数据。
- 订单异常 3 分钟演示脚本与录屏。
- 28 条 Golden Tasks 与自动评测报告。
- Trace 时间线、审批记录、审计记录和失败注入记录。
- MVP 设计规格与更新的系统设计文档。

### JD 对齐交付物

- ERP Adapter、聚水潭契约 mock 与契约测试。
- SKILL 注册表、订单异常/退款判定技能。
- Memory/失败记忆与反思闭环。
- RAG 退款资格判定与政策引用。
- Playwright 旧系统 RPA 演示。
- 模型网关、路由与成本对比。
- 60+ Golden Tasks 评测报告、5 分钟演示、ADR、面试问答卡。

### v1.0 交付物

- 三个场景的演示脚本与 3–5 分钟录屏。
- 100 条 Golden Tasks 与自动评测报告。
- README（业务背景、架构图、指标、快速开始）。
- 3–5 篇架构决策记录（DAG vs ReAct、验证隔离、写操作审批、RAG 通道选择）。
- 简历条目与面试问答卡。

质量指标与验收证据见[系统设计 · 质量目标](design.md#13-质量目标)、[MVP 设计规格 · 评测设计](specs/2026-11-04-mvp-order-exception-design.md#9-评测设计)和 [JD 对齐设计方案](specs/2026-11-04-jd-alignment-design.md#5-评测与验收)。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 6 周范围过大 | 按切线规则保 Adapter/SKILL、RAG、评测；RPA 和多模型可降级 |
| 3 周 MVP 延期 | 砍控制台样式和真实模型冒烟，不砍审批、幂等、补偿、审计 |
| 聚水潭契约 mock 被质疑为假 | Adapter 接口 + 契约测试 + 可替换真实端点；文档写清限制 |
| RAG 质量不足 | 小语料高精度、强制引用、评估集覆盖冲突/过期政策 |
| RPA 脆弱 | 确定性选择器、截图、重试、人工确认；只做兜底 |
| 模型成本/延迟 | 强弱模型路由、缓存、stub 测试、成本看板 |
| 范围膨胀 | 场景锁定订单异常；新增需求进入 backlog，不进入当前版本 |
| 模型不稳定 | stub 模型跑测试，真实模型只跑冒烟；提示词与模型变更必须回归 |
| 数据许可 | 原始数据不入仓，提供下载脚本；非商业数据集只用于本地演示并署名 |
| 演示环境故障 | 提供录屏与预置快照，面试现场可离线运行 |
| 商用经验不足 | 不伪造；补真实试点/设计合作伙伴，面试明确边界 |
| 「像 Demo」质疑 | 用失败注入、幂等、补偿、审计、评测报告五项证据回应 |
